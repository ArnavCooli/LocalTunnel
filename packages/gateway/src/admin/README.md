# Gateway Admin API

The management API the desktop app uses. It speaks ordinary HTTP/1.1 inside a TLS
connection whose ALPN is `lt-admin/1`, so it shares port 443 with public traffic
while remaining invisible to anything that does not ask for that protocol.

**Authentication:** `Authorization: Bearer <admin token>` on every request. The token
is generated by the installer and shown once; the gateway stores only its SHA-256
hash and compares in constant time. Five failures from one IP in 15 minutes locks
that IP out.

**Transport trust:** the gateway presents its self-signed identity certificate. The
client is expected to pin its fingerprint (captured over SSH at install time) rather
than to verify a chain.

There is deliberately **no endpoint that runs a command, reads a file, or writes
outside the gateway's own state**. Compromising the admin token gets an attacker the
user's tunnel configuration, not a shell.

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/v1/status` | Everything at once: gateway info, machines, services, certificates, open ports. This is what the UI polls. |
| `GET` | `/v1/machines` | List machines. |
| `GET` | `/v1/machines/:id` | One machine. |
| `PATCH` | `/v1/machines/:id` | Rename. Body: `{ "name": "…" }`. |
| `POST` | `/v1/machines/enroll-token` | Mint a single-use, 15-minute enrolment token. The plaintext is returned exactly once. |
| `POST` | `/v1/machines/:id/revoke` | Revoke. Closes the live tunnel immediately and rejects future handshakes. |
| `DELETE` | `/v1/machines/:id` | Revoke and forget, including its services. |
| `GET` | `/v1/services` | List services with live status. |
| `POST` | `/v1/services` | Publish a service. |
| `PATCH` | `/v1/services/:id` | Change `name`, `enabled`, `localHost`, `localPort`. |
| `DELETE` | `/v1/services/:id` | Unpublish. Closes any public port it held. |
| `GET` | `/v1/certificates` | Certificate state per hostname. |
| `POST` | `/v1/certificates/:hostname/issue` | Force a (re)issue. |
| `GET` | `/v1/diagnostics[?serviceId=]` | What the gateway itself can see about a service. |

## Creating a service

```json
POST /v1/services
{
  "machineId": "m_7f3a…",
  "name": "My Website",
  "type": "http",            // http | https | tcp | udp
  "localHost": "127.0.0.1",
  "localPort": 3000,
  "hostname": "mysite.example.com",   // required for http/https
  "publicPort": null,                 // required for tcp/udp
  "allowLanTarget": false,
  "expiresAt": null                   // ISO timestamp for a temporary link
}
```

Validation errors come back as `400` with a message written for a person:

```json
{ "error": "mysite.example.com is already used by \"Old site\"" }
```

Publishing a web service triggers certificate issuance in the background; publishing a
TCP/UDP service opens its public port and adds the host firewall rule. Both are
reversed on delete.

## Status shape

`GET /v1/status` returns each service enriched with what the gateway knows right now:

```jsonc
{
  "id": "svc_1",
  "status": "online",          // online | disabled | machine_offline | local_unreachable
  "machineConnected": true,
  "localReachable": true,      // from the agent's own probe of localhost:3000
  "localError": null,
  "certificate": { "state": "valid", "expiresAt": "2027-04-18T…", "autoRenew": true },
  "publicUrl": "https://mysite.example.com",
  "stats": { "requests": 18432, "status2xx": 18100, "bytesIn": 91234, … }
}
```

The `status` field is what the UI's coloured dot reflects, and `localError` is the
sentence shown under it when something is wrong.
